# go24

Self-hosted таск-трекер и система ведения проектов на Go вместо корпоративного портала, по образцу задач корпоративного портала и OpenProject. Всё разворачивается на своих серверах, облачные сервисы не используются. Каждый компонент работает в своём Docker-контейнере, а всё, что можно, отдано готовым open-source продуктам, которые тоже ставятся на свои серверы:

| Задача | Чем решаем |
|---|---|
| Вход, пользователи, группы, 2FA | [Authentik](https://goauthentik.io) (OIDC) |
| Хранение файлов в любом своём хранилище (диск, SFTP, Garage/SeaweedFS, Nextcloud) | [rclone](https://rclone.org) `serve s3` |
| Данные CRM | PostgreSQL |
| Бизнес-логика и интерфейс | go24 (Go, `net/http`, `html/template`) |

Схема и принятые решения описаны в [docs/architecture.md](docs/architecture.md).
Оформление меняется через CSS без пересборки, все цвета и иконки — в переменных. Подробно — в [docs/theming.md](docs/theming.md).
Языки интерфейса (сейчас русский и английский) — в отдельных файлах переводов, свой язык можно добавить без пересборки: [docs/i18n.md](docs/i18n.md).

## Что уже умеет

- **Проекты** с ключом (`GO`, `CRM`…) и участниками в ролях «владелец», «руководитель», «участник», «наблюдатель».
- **Задачи** `GO-1`, `GO-2`… с ролями: постановщик, исполнитель, соисполнители, наблюдатели.
- **Статусы и действия:** ждёт выполнения, выполняется, ждёт контроля, завершена, отложена. Действия: начать, приостановить, завершить, отложить, возобновить. Есть контроль результата: постановщик принимает работу или возвращает её на доработку.
- **Подзадачи, чек-листы, комментарии, история изменений.** Одновременная правка не затирает чужие изменения (защита по `version`).
- **Все задачи**: всё, что вам доступно, с фильтром по проекту; в режиме администратора — все задачи go24. Счётчики в меню кликабельны: просроченные, открытые, ждут вашего контроля.
- **Видимость задач проекта**: «все участники проекта» или «только участники задачи» (как задачи без группы в корпоративном портале; так настроен импорт `EXT`).
- **«Мои задачи»** с вкладками «Делаю», «Помогаю», «Поручил», «Наблюдаю», просроченные задачи подсвечены.
- **«Мой план»**: личная доска с колонками «Не распланировано», «Сегодня», «На этой неделе», «Позже» и своими, перетаскивание задач; статусы не меняются, план видит только владелец.
- **Учёт времени**: таймер на задаче (один на пользователя, виден в верхней строке), ручное добавление (`1:30`, `90m`, `1.5`), плановая оценка и прогресс «потрачено из оценки».
- **Диаграмма Ганта** проекта: плановые даты, связи «закончить → начать» (без циклов), нарушенные связи красным, масштаб дни/недели/месяцы, линия «сегодня»; рисуется SVG на сервере и подчиняется теме.
- **Канбан проекта**: колонки по статусам, карточку можно перетащить мышью. Перенос срабатывает, только если workflow разрешает его вашей роли.
- **API-ключи и REST API v1** — описание ниже.
- **Режим администратора** для группы `go24-admins` в Authentik: кнопка в верхней строке, показывает все проекты и задачи. Личные чаты и личные группы администратору не видны никогда.
- **Импорт из корпоративного портала** с обезличиванием людей (ФИО, телефоны, почта) — [docs/import-legacy.md](docs/import-legacy.md).
- **Хранилища** (раздел в меню): каждый подключает своё хранилище — Nextcloud/WebDAV, SFTP, S3, FTP — через rclone rcd. Вложения задач, доступ к файлам — по видимости задачи. Безопасность: только разрешённые типы, внутренние адреса — только администратору, отдельная сеть Docker для rclone.
- **Файлы** хранятся через rclone.

## REST API v1

Ключ создаётся на странице «API-ключи». Права выбираются при создании: `projects:read`, `projects:write`, `tasks:read`, `tasks:write`. Ключ показывается один раз, в базе хранится только его хеш. Ключ передаётся в заголовке:

```bash
curl -H "Authorization: Bearer go24_<id>_<secret>" http://192.168.1.15:8080/api/v1/me
```

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/v1/me` | Владелец ключа и права ключа |
| GET, POST | `/api/v1/projects` | Мои проекты / создать проект `{key, name, description}` |
| GET | `/api/v1/projects/{KEY}` | Проект и его участники |
| GET, POST | `/api/v1/projects/{KEY}/tasks` | Задачи проекта (`?all=1` — включая завершённые) / создать задачу |
| GET | `/api/v1/tasks?role=responsible\|accomplice\|creator\|auditor` | «Мои задачи» |
| GET, PATCH, DELETE | `/api/v1/tasks/{KEY-N}` | Карточка задачи / частичное изменение, нужен `version` из последнего чтения / в корзину (постановщик или администратор) |
| GET | `/api/v1/efficiency?from=YYYY-MM-DD&to=YYYY-MM-DD` | Эффективность владельца ключа за период (по умолчанию текущий месяц): процент, задачи, нарушения |
| GET, POST | `/api/v1/flows`, `/api/v1/flows/{id}/tasks` | Потоки: список со счётчиками, создание `{name, project, distribution: manually\|queue\|himself, planned_minutes, members}`; задача в поток `{title, description}` — исполнителя и срок назначит поток |
| GET, POST, DELETE | `/api/v1/mail/boxes`, `/api/v1/mail/boxes/{id}/sync`, `/api/v1/mail/boxes/{id}/folders`, `/api/v1/mail/folders/{id}/rename`, `/api/v1/mail/folders/{id}`, `/api/v1/mail/messages?folder=ID\|all\|flagged\|snoozed\|cat:ID&q=&conv=1`, `/api/v1/mail/messages/{id}`, `/api/v1/mail/messages/{id}/conversation`, `/api/v1/mail/move`, `/api/v1/mail/act`, `/api/v1/mail/categories` | Почта (права `mail:read`, `mail:write`): свои ящики с папками и счётчиками, подключение ящика, обновление, папки — создать `{name, parent}`, переименовать `{name}`, удалить; письма папки, «Все входящие», «С флажком», «Отложенные» или категории (`conv=1` — беседами), письмо и вся беседа (помечаются прочитанными), перенос `{letters, folder}`, действия `{letters, action, arg}` (прочитано, флажок со сроком, закрепить, категория, отложить, архив, удалить, спам), категории |
| POST | `/api/v1/tasks/{KEY-N}/take` | «Взять в работу» задачу потока с самостоятельным распределением |
| GET, POST | `/api/v1/trash`, `/api/v1/trash/{id}/restore` | Корзина задач: удалённые задачи / восстановить с подзадачами |
| POST | `/api/v1/tasks/{KEY-N}/actions/{action}` | `start`, `pause`, `complete`, `approve`, `disapprove`, `defer`, `renew` |
| POST | `/api/v1/tasks/{KEY-N}/comments` | Комментарий `{body}` |
| POST, DELETE | `/api/v1/tasks/{KEY-N}/checklist[/{id}]`, `.../checklist/{id}/toggle` | Чек-лист |
| POST | `/api/v1/tasks/{KEY-N}/tags` | Тег задачи `{tag, remove}` (карточка задачи в API отдаёт `tags`, `links`, `files`) |
| POST, DELETE | `/api/v1/tasks/{KEY-N}/links[/{id}]` | «Связанные задачи»: `{pred: KEY}` — задача идёт после KEY; удалить связь |
| POST | `/api/v1/tasks/{KEY-N}/files` | Вложение к задаче (multipart, поле `file`; скриншот, лог) |
| POST, DELETE | `/api/v1/tasks/{KEY-N}/participants[/{role}/{user_id}]` | Соисполнители и наблюдатели |
| PATCH | `/api/v1/tasks/{KEY-N}` с `start_plan`, `end_plan`, `estimate_minutes` | Плановые даты и оценка |
| POST | `/api/v1/tasks/{KEY-N}/time` | Добавить время `{duration: "1:30", date, comment}` |
| POST | `/api/v1/tasks/{KEY-N}/timer/start`, `/api/v1/timer/stop` | Таймер |

Коды ответов: `401` — нет ключа или ключ неверный, `403` — нет права или роли, `404` — не найдено, `409` — задачу уже изменили (перечитайте и повторите), `422` — ошибка во входных данных. Ответ на любое действие с задачей — её актуальная карточка, где `actions` — что вам доступно сейчас.

## Структура

```
cmd/go24/              точка входа
internal/config        настройки из переменных окружения
internal/auth          вход через Authentik (OIDC), подписанные cookie-сессии
internal/db            подключение к Postgres и встроенные миграции (migrations/*.sql)
internal/storage       файлы через S3 API rclone
internal/tasks         таск-трекер: статусы и роли (workflow.go), хранилище в Postgres (store.go)
internal/web           HTTP-обработчики и шаблоны страниц (templates/)
deploy/                docker compose, шаблон .env, rclone.conf, инициализация Postgres
```

## Запуск на сервере разработки (192.168.1.15)

Код правим на Mac, собираем и запускаем в Docker на сервере. Go на Mac не нужен.

```bash
make sync                    # залить код в /srv/go24
make secrets                 # один раз: создать deploy/.env со случайными паролями
make up                      # собрать и запустить стек
make ps                      # статус контейнеров
make logs s=go24             # логи сервиса
make test                    # go vet + модульные тесты (в контейнере golang)
make test-db                 # интеграционные тесты на отдельной базе go24_test
make test-storages           # сквозной тест хранилищ через rclone rcd и временный WebDAV
make test-js                 # сценарии перетаскивания на досках в jsdom
```

Перед первым запуском на сервере нужно положить `deploy/rclone/rclone.conf`: скопировать `rclone.conf.example`, а для разработки хватит remote `local`.

### Первичная настройка Authentik

Приложение go24 (OIDC-провайдер) создаётся в Authentik автоматически из blueprint [deploy/authentik/blueprints/go24.yaml](deploy/authentik/blueprints/go24.yaml). Client ID и секрет генерирует `make secrets`.

1. В `deploy/.env` указать `BIND_IP`, `GO24_BASE_URL=http://<BIND_IP>:8080` и `GO24_OIDC_ISSUER=http://<BIND_IP>:9000/application/o/go24/`, затем выполнить `make up`.
2. Один раз открыть `http://<BIND_IP>:9000/if/flow/initial-setup/` и задать пароль администратора `akadmin`.
3. Войти в go24 по адресу `http://<BIND_IP>:8080`.

### Доступ к сервисам при разработке

Порты слушают только `127.0.0.1` на сервере. Чтобы открыть их на Mac, поднимите SSH-туннель:

```bash
make tunnel
```

После этого go24 доступен на http://127.0.0.1:8080, а Authentik — на http://127.0.0.1:9000.

Принципы self-hosted описаны в [docs/selfhosted.md](docs/selfhosted.md).
