# Interface Languages

All interface texts, error messages, and status names are extracted into translation files. Only keys remain in code and templates.

| Where | What |
|---|---|
| `internal/i18n/locales/ru-RU.json` | Russian, default language: if a key is missing in another language, it is taken from here |
| `internal/i18n/locales/en-US.json` | English |
| `deploy/locales/<code>.json` | Languages and overrides for a specific installation, without rebuild (picked up upon go24 restart) |

The file is a flat JSON `"key": "text"`. Substitutions work like in `fmt.Sprintf`: `"err.project_key_taken": "Project with key %s already exists"`. The date format is defined in the language itself (`format.datetime` in Go notation: `02.01.2006 15:04` or `Jan 2, 2006 15:04`).

## How the language is selected

1. Explicit user selection: language links at the bottom of the left sidebar and on the login page (`/lang/<code>`), remembered in a cookie for one year.
2. Browser language (`Accept-Language`): exact match (`en-US`), then by primary language (`en-GB` → `en-US`).
3. Otherwise `ru-RU`.

The REST API responds in the language from `Accept-Language`. In errors, in addition to the text, there is a stable `code` (message key), which applications use to verify the error.

## Adding a language

- **Without rebuild:** copy `en-US.json` to `deploy/locales/de-DE.json`, translate it, and run `make up`. You don't have to translate everything: missing keys will fall back to Russian.
- **Built into the product:** place the file in `internal/i18n/locales/`. The `TestLocalesComplete` test requires all keys to be present in built-in languages.

## Developer rules

- In templates: `{{t "nav.projects"}}`, with substitutions `{{t "search.found" .Query (len .Data)}}`, for sets of values `{{t (print "status." .Status)}}`.
- In Go: errors for the user — `i18n.E("err.key", args...)`, key argument — `i18n.Ref("status.completed")`. Do not write Russian text in code.
- Change history stores codes (`in_progress`, `2`, `true`, timestamp in RFC 3339) rather than text: history is displayed in the reader's language.
- The `TestMessageKeys` test finds all keys in templates and Go code and checks that they exist in all languages. The page rendering test catches untranslated keys on the page.
